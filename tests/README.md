# Application tests

This is the dedicated directory for application test code and fixtures, including tests for application tooling. P01 adds explicitly wired Cargo test targets and private test modules; see the [P01 guide](../docs/app/p01/README.md). P00 tooling tests are under `tests/tooling/`, with synthetic inputs under [fixtures/p00](fixtures/p00/README.md); ignored analysis-tool regression tests remain separate local reference checks.

Run `python3 -m unittest discover -s tests/tooling -p 'test_*.py'` from the repository root with Python 3.11+, Node 22.22.2+ and Git. The optional source-audit parser regression requires `P00_TYPESCRIPT` pointing to TypeScript 6.0.3; it reports a skip otherwise. Set that variable for the full P00 reference check as described in the [run record](../docs/app/baseline/reference-run.md). The default Python suite needs only tracked inputs. Cargo/native/browser experiments are separate commands with distinct evidence and external prerequisites.

P00 reference scenarios are under `tests/reference/`; saved queue, persistence, scrobble and redacted live-server evidence is under `tests/fixtures/p00/`. Optional store/callback reproduction tests also need `P00_REFERENCE_ROOT` and `P00_ESBUILD` (the frozen reference esbuild module). Default artifact/redaction checks still run without those dependencies. The queue benchmark emits raw samples and is run separately, not as a repeated timing assertion in the unit suite. Full commands and limitations are in the [headless guide](../docs/app/baseline/headless-characterization.md) and [server runbook](../docs/app/baseline/live-servers.md).

The [adapter replay](../docs/app/baseline/adapter-characterization.md) adds 54 controller/client/interceptor/normalizer cases using saved live responses and explicit synthetic transport. Optional reproduction and origin-rejection tests use `P00_REFERENCE_ROOT`/`P00_ESBUILD`; default provenance, payload, identity and modified-source rejection tests use tracked inputs. The harness opens no sockets and does not run the application UI.

Organize tests by owning crate/feature and test kind as they are implemented. Suggested areas are unit tests, integration/backend/engine tests, fixtures, performance tests and shared test support; create them only when needed. Use redacted, disposable data and keep required inputs tracked.

P01 explicitly connects files here to their owning Cargo packages through test targets or private test-module wiring, and configures CI to execute them. `cargo test --workspace --locked` runs the portable/model/worker/UI/IPC tests; optional real-engine, capture and benchmark tests are ignored by default. The browser scenario under `tests/browser/` is an optional isolated integration experiment. Tests in a virtual workspace's root are not discovered merely because this directory exists. Include tests needing private internals under the owning crate's `cfg(test)` boundary without widening production visibility. Document the actual commands in [app documentation](../docs/app/README.md) once validated.

Follow [AGENTS.md](../AGENTS.md): implement -> test -> fix/retest until passing -> two independent reviews -> fix/retest until passing -> commit/push. A fix requires rerunning the reproducing test when applicable, relevant regressions and affected checks; earlier passing results do not validate changed code.

Optional original-UI scenarios under `tests/reference/` use external Playwright/Electron and controlled disposable profiles/services; see the [browser/desktop/remote guide](../docs/app/baseline/browser-characterization.md). The generic browser environment is independent infrastructure and is not required by default artifact tests, application builds or CI. Saved screenshot/DOM/source hashes and selected observed flows are checked with tracked inputs only.

The [P01 continuation](../docs/app/p01/continuation.md) wires `tests/native-spike/analysis_session.rs`, extends the actual RawInput keyboard test and adds an explicitly ignored Unix concurrent workload under the owning UI crate's private test boundary. `tests/desktop/accessibility.py` is an optional isolated AT-SPI/AppImage audit, not a screen-reader certification. The browser scenario optionally reads private loopback Navidrome fixture URLs; it never saves or prints them.

Unix P01 native tests execute the tracked `fake_mpv.py` / `fake_capture.py` fixtures through temporary named symlinks. Preserve their Git executable modes in copied inputs; writing executable fixtures immediately before concurrent process launch can race inherited write descriptors. These fixtures generate only owned protocol/PCM data.

P01.03 session reorder tests are wired as the model `reorder` Cargo integration target and the UI private `drag_tests` module. They cover real egui pointer events, selected-track order, whole-album moves, repeated operations, filtered selection, rejected cross-album/stale drops, a generated vector oracle and cancellation across 100k records. These are synthetic view operations, not queue or playlist mutations.

The native CI wrapper defaults to workspace tests. `python3 tools/app/test-native.py --external-audio` runs the five explicitly ignored native audio/capture probes only with the isolated owned sink/server described in the P01 guide. Both modes preserve Cargo failure status and publish only failed Rust identifiers as CI annotations.

Windows IPC tests are wired as `windows_pipe` (three integration tests) plus a private `mpv::transport` test (server PID mismatch). Cargo builds the tracked `p01-pipe-peer` fixture binary from `tests/native-spike/windows_peer.rs`; non-Windows builds use an empty entry point. It is not included by desktop-package builds/AppImage packaging. Windows tests hard-link the immutable fixture under a temporary mode name on the same volume, without requiring developer-mode/symlink permission. Hosted Windows execution and real mpv remain distinct from cross-compilation.

The private UI accessibility regression is included from `tests/spike-ui/accessibility.rs`. The optional `tests/desktop/orca.py` journey uses installed Orca/Speech Dispatcher/eSpeak NG with isolated profiles and an owned null sink; default tooling tests cover its filtering/isolation/cleanup and saved before/after evidence without GUI dependencies. See the [screen-reader record](../docs/app/p01/screen-reader.md) for prerequisites and limits.

The browser seek experiment now retains the non-looping default in its main journey and separately compares direct seeks with looping off/on in fresh pages. It needs a functioning isolated audio service; [the seek record](../docs/app/p01/browser-seeking.md) documents the owned null sink and the distinction between completed experiments and open seeking gates.

`tests/browser/seek-lifecycle.cjs` extends the optional browser journey with caught setter rejection, missing completion/deadline, same-position, cancellation/source replacement, callback/native failed-resume, visible recovery and pending-shutdown checks. It injects fixture setter faults explicitly; real completion events are not fabricated. The [lifecycle record](../docs/app/p01/seek-deadlines.md) distinguishes these regressions from browser/device certification.

The private Linux `mpv::transition_tests` module includes `tests/native-spike/transitions.rs`: four default PCM-detector/failure/deadline tests and an explicitly ignored owned-monitor current/next/prefetch experiment. The [native transition record](../docs/app/p01/native-transitions.md) gives isolated setup and measurement limits. Default CI never starts this capture; the existing five external native probes retain their exact scope.

The model `fade` Cargo test target uses the tracked crossfade fixture and no ignored reference inputs. `tests/reference/p01-crossfade.cjs` optionally replays hash-pinned original functions with TypeScript 6.0.3; default tooling tests reject modified source before evaluation. Linux-only calibration/crossfade tests are included under the existing private mpv transition test module and remain explicitly opt-in. See the [crossfade record](../docs/app/p01/crossfade.md) for state/clock/platform limits.

`tests/browser/native-seek-lifecycle.cjs` extends the optional WASM browser journey with actual element seek events, replacement in both directions, withheld completion, mismatch, reload/source cancellation and pending native-seek shutdown. It does not fabricate completion events or certify physical scrubber input. See the [element-seek record](../docs/app/p01/native-control-seeking.md).
