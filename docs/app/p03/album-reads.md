# Album and album-artist detail reads

`feishin_subsonic::get_album` and `get_album_artist` implement two bounded P03.03 reads over the existing local ProtocolTransport. Both send authenticated GET requests with only the requested ID and reuse fixed HTTP/protocol errors, response correlation, byte limits, cancellation and inclusive operation deadlines. No production HTTP client, UI, mutation, retry or list-pagination implementation is added.

Album detail returns the existing normalized Album, including ordered nested songs, album artists/participants/genres, labels, release metadata and disc titles. Duplicate disc-title keys keep the last value. Disc subtitles use the raw nullable disc number, preserving the distinction between source nullish lookup and the normalized zero-to-one disc-number fallback. Nested songs reuse the tested song normalizer; no playlist-entry ID is invented. Missing/null song arrays normalize to an empty present song list.

Album-artist detail returns the new portable AlbumArtistDetail wrapper. It carries an AlbumArtist with source defaults and optional embedded albums; absent/null albums differ from an explicit empty vector. Similar artists remain absent as the source controller requires. Supplied enrichment arrays are type/budget checked rather than copied into a result the controller discards. Server scope is retained on all nested entities and genres; repeated song IDs remain distinct rows.

[ADR-016](../adr/016-subsonic-album-reads.md) records the source observations and deliberate differences: missing/null album title falls back to name for required sortName; numeric conversions and disc-map keys are checked; malformed count strings fail; root ID mismatch is stale. The source controllers do not themselves reject root ID mismatch. Profile server IDs are nonblank and <=128 UTF-8 bytes; callers bind the selected base/auth/profile. Raw backend IDs retain request-construction limits.

The nested item budget counts root/nested entities and supplied metadata rows across the whole response, in addition to existing per-array checks. It is a work bound, not heap introspection; source JSON and normalized values can coexist, and scalar fallback metadata is not separately charged. Transport receive allocation, scheduling and cancellation wakeups remain concrete transport responsibilities. Completion checks apply even when normalization failed.

The [top-level album_reads target](../../../tests/subsonic/album_reads.rs) compares every emitted field with original controller/normalizer fixtures. Test-only shared song projection helpers live in tests/subsonic/support; production serialization is not added to domain. [Default tooling guards](../../../tests/tooling/test_p03_album_reads.py) validate provenance and reject changed source before loading the compiler. [Verification](album-reads-verification.md) records exact results. Remaining P03.03 reads, P03.04 paging/counting, artist info/enrichment, application adoption, live conformance and all phase exits remain open.
