# Bounded copied import projection (P02.05)

The [portable importer](../../../crates/storage/src/imports.rs) accepts borrowed bytes supplied explicitly by the caller. It discovers no profile directory, opens no source files, changes no source bytes and makes no storage writes. `preview` produces one immutable candidate plus a typed report. The [import journal](../../../crates/storage/src/journal.rs) prepares, applies and rolls back that exact candidate in its independent development namespace. Neither importer nor journal is connected to a shell or playback owner yet.

This is a useful partial projection, not complete P02.05, settings migration, P05 queue restoration or a phase exit. Every report has `partial: true`; fields outside the closed target schema are omitted with typed diagnostics. Arbitrary source JSON, credentials and runtime player state are never retained in the candidate or its backup. The caller must present that partial result before deciding whether to apply it.

## Accepted copies and version matrix

| Copy | Supported shapes | Other versions and corruption |
| --- | --- | --- |
| Settings | Raw category object or `{state, version}` with integer version 14 through 34 | Missing, malformed or unsupported version fails. Versions 0-13 and future versions are unsupported. Retained columns and supplied Auto DJ objects receive the documented historical transforms; other transformations remain deferred and pre-v34 copies report `DeferredMigrations` |
| Split settings | Typed category-to-byte map, plus copied version 14 through 34; absent version means 14 as in source | Each corrupt category reports `CorruptCategory` and preserves its target baseline. Unsupported explicit version fails |
| Authentication | `{state: {serverList, currentServer}, version: 2}` | Other versions fail; invalid individual server records report rejection; malformed whole shapes fail |
| Player | `{state: {player, queue?}, version: 3 or 4}` | Versions below 3 and above 4 fail explicitly; no older queue reset/migration is claimed |
| Separate queue | Raw queue object supplied alongside a supported player copy | A present separate queue wins over embedded data, including when it is corrupt. Corrupt split data reports rejection and never falls back to the embedded queue. A separate queue without a player envelope is rejected in the report |
| Timestamp | Raw numeric seconds, or `{state: {timestamp}, version: 1}` | Other envelope versions fail; negative, overflowing, nonnumeric or unmatched positions report rejection |

A supplied split general category marks the split settings copies authoritative, including when that general category is corrupt. The combined copy is then ignored. Without that marker, a valid supplied combined copy projects its categories first. Supplied split categories absent from the combined copy supplement it; an existing split Auto DJ category also wins, matching the legacy helper's treatment of that category. Other duplicate split categories report `IgnoredSplitCopy`. This imports copies only; it never performs the source helper's split-key writes. A malformed whole combined document fails rather than guessing how to salvage mixed copies.

## Retained fields and recovery rules

General settings retain `language` and `followSystemTheme` in `ProfileData.preferences`. Each field validates independently; invalid values preserve the existing target value. Unsupported general fields and other categories report their omission without copying raw keys or values.

Lists retain table and detail column configurations using closed list, column, alignment and pin vocabularies from the pinned source. A supplied valid `columns` array is migrated for its source version and then replaces the complete corresponding target array. Existing order/properties survive; a current-version empty array stays empty, while an older empty array receives applicable disabled additions. Arrays are never merged by index. Duplicate IDs, invalid widths, invalid entries and more than 64 columns reject that one list/view array with a list-specific diagnostic and preserve its baseline. Widths must be finite and between 0 and 16384. At most 36 list/view pairs are retained. Other layout, filtering, grid and table/detail options remain deferred.

Auto DJ retains the exact source schema: `albumStrategy` and `songStrategy` (`similar` or `library_random`), mode (`songs` or `albums`), `allowDuplicates`, `enabled`, `onlySimilar`, `itemCount` and `timing`. Finite numeric values, including fractional values accepted by the source schema, are preserved using JSON numbers. An invalid/unknown field rejects the category. For versions before 28, supplied legacy objects receive strategy/mode normalization and missing-field defaults; v28+ remains strict. Absent whole categories are preserved with an explicit older-copy warning. Execution/refill behavior remains deferred. Retaining combined Auto DJ when no split Auto DJ exists deliberately avoids the isolated unused helper's omission, as required by [ADR-009](../adr/009-source-differences.md); this does not characterize it as an active current UI defect.

Authentication retains only validated ID, name, HTTP(S) endpoint and backend kind in the existing non-secret profile schema. Record map keys must match IDs. URL userinfo, query and fragments are rejected; intentional LAN endpoints/base paths remain allowed. `credential`, `ndCredential`, `savePassword`, user/device identifiers, remote URLs, capabilities and other fields are omitted, with credential-stripping and unsupported-field warnings. A selected server must resolve to a retained profile; otherwise selection is cleared. This chooses no remember-credential policy and does not import tokens into a secret store.

Queue default IDs identify occurrences. Repeated song IDs remain separate occurrences; duplicate occurrence IDs keep the first entry and report the duplicate. Song-map entries absent from default order are dropped. Missing/invalid song records report their ordinal location and are skipped. The map key is authoritative; optional `_uniqueId` must agree when present. Only occurrence/song/server IDs, title and duration survive; stream/artwork URLs, local paths, metadata and player runtime fields are dropped. IDs are bounded to 128 bytes and titles to 1024 bytes. The target queue is a durable DTO, not a second playback owner.

Priority IDs retain order after removing dangling/duplicate entries with diagnostics. Active track shuffle with a nonempty permutation requires a complete valid permutation of retained default occurrences; invalid permutations or unsupported shuffle modes clear the permutation and current selection with diagnostics. Disabled shuffle, album shuffle and track shuffle with an empty permutation use default order, matching `isShuffleEnabled` at `player.store.ts:165-168`. Album/disabled shuffle ignore the inactive permutation. The current occurrence resolves the source player index through the active permutation, never by song ID; if it is invalid, no guessed selection is made. Source `getQueueOrder` (`player.store.ts:1101-1119`) compacts missing song-map entries before `getCurrentSong` (`982-994`) indexes that order. The target deliberately applies a stricter corrupt-state policy: whenever validation removes or deduplicates any default occurrence, default-order modes clear the current occurrence and reject its copied timestamp. Valid occurrence data and priority order still survive. This avoids attaching a timestamp using an ambiguous raw or compacted index; it is a documented safety difference, not parity with source corruption recovery. See [ADR-004](../adr/004-persistence.md). No reordering, playback engine state, readiness, repeat, volume or automatic playback is inferred.

Normalized source song duration is already milliseconds (`navidrome-normalize.ts:281`, `subsonic-normalize.ts:212`, `jellyfin-normalize.ts:175`); it is range checked and truncated to integer milliseconds. Separate timestamp seconds are checked before multiplication by 1000 and truncation. A timestamp can only attach to a valid current occurrence in a queue imported in the same preview. It cannot attach to an old baseline queue or another occurrence of the same song. Domain conversion methods expose distinct occurrence IDs, server-scoped song IDs, milliseconds and playback position without adding Serde to the domain crate.

## Bounds, evidence and checks

The total supplied bytes across all copies must be at most 2 MiB. Each source default/song map/priority array is limited to 10000 entries; the serialized candidate must be at most 256 KiB. Journal envelope limits may reject a smaller candidate when its previous revision must also fit. Reports contain at most 64 fixed-code diagnostics plus an omitted count, typed categories, known list IDs and bounded ordinal indexes. Errors contain no source parser messages, raw keys or payload values. Durable deserialization denies unknown fields and `validate_data` rechecks profile, column, queue, identity/permutation/current-position and byte bounds for both current and previous journal revisions.

The [import tests](../../../tests/storage/imports.rs) use the existing captured [current v34 settings export](../../../tests/fixtures/p00/browser/2026-10-22/navidrome-current-settings-export.json) directly. Historical copies under [imports fixtures](../../../tests/fixtures/p02/imports/) are synthetic/source-derived, not older real-user exports. The source-characterized v3 fixture in [state traces](../../../tests/fixtures/p00/state-traces.json) is also replayed. There is no historical real-user export corpus; compatibility outside this explicit matrix remains unverified.

The [historical transform continuation](settings-history.md) documents versions 14-34, source replay, deliberate differences and remaining gaps.
