# Bounded portable query cache

P02.07 now has `feishin_domain::query_cache`, with no new crate/dependency or filesystem/browser/network implementation in domain code. This is a reusable in-memory foundation, not a backend adapter, production queue reducer or UI query manager.

`QueryKey` factories accept the existing song, album, artist, album-artist, genre, playlist and user list queries, a `ListKind` and explicit `LibraryScope`. All current query fields participate, including server/sort/direction/page/limit/search and each modeled filter. Library context is encoded in addition to explicit filter folder IDs. None versus empty, vector ordering and count pagination remain distinct. The detail factory identifies server/item/ID/library only; endpoint-specific extra parameters need a typed extension or cache bypass. No global cross-server player/lyrics cache is exposed.

Keys reject IDs over 128 bytes, search over 1,024 bytes, role over 256 bytes, ID vectors over 64 entries and full encoded identity over 16 KiB. The internal schema-v1 encoding is unambiguous and not a persisted-cache or backend wire contract. Key Debug hides raw identifiers/filter text. The cache's fixed 49-byte diagnostic contains version, server/entry/pending counts, accounted bytes/items and retained-entry encoded-key bytes. Its final field excludes pending-key copies and heap overhead; raw keys/values never appear.

`QueryCache::new` takes a caller-owned nonzero instance ID and validated limits. Defaults/maxima: 64 servers, 256 entries, 32 pending requests, 4 MiB accounted value bytes, 10,000 total items, 1 MiB/10,000 items per value. Values may contain Rc and need no Send/Debug/Clone bound. Producer-supplied `Weight` must reflect the normalized result; the cache does not inspect arbitrary object heaps. Adapters must enforce actual wire/normalization budgets before supplying values. Key storage is separately bounded by entry/pending counts and the key cap.

Register a server, then `begin` with a key, monotonic Milliseconds now and deadline. A successful newer begin of the same key cancels/supersedes its predecessor. An opaque ticket exposes a typed RequestContext and cancellation interface. `complete` validates exact outstanding identity/generation, cancellation and deadline before publishing a value. At the deadline, work is expired. Failed/oversized updates leave prior cached data intact; errors are returned rather than negative-cached or retried. Successful updates use checked accounting and deterministic LRU eviction.

`get` returns a borrowed value plus Fresh/Stale. Freshness lasts 10 seconds from insertion; idle expiry is 20 seconds from last use/insertion. Maintenance occurs through owner operations/`maintain`; no background timer exists. This is an explicit target idle policy, not source observer-GC parity. Clock regression and counter exhaustion fail explicitly.

`cancel(ticket)` affects only that outstanding request. `cancel_server` cancels pending requests while retaining data. `invalidate_server` cancels/removes data and advances its generation; `invalidate_family` does so for one server/entity family. `remove_server` also frees registration. Old completions after removal/re-registration cannot revive data, and foreign-instance tickets cannot consume live work. Dropping an owner marks still-pending tokens cancelled. Actual HTTP/task abortion, logout/mutation UI binding and retry policy remain consumer work.

Source anchors, intentional policy differences and limitations are in [ADR-007](../adr/007-query-cache.md) and [the migration map](../migration/p02-cache.csv). Source count keys retain pagination; omitted source global/player/lyrics/image/folder/tag/custom keys and all mutation-specific optimistic updates remain deferred. The imported queue subset remains bounded by storage; complete runtime queue/query wire serialization and diagnostic integrations remain open.

The explicitly wired [tests](../../../tests/domain/query_cache.rs) use fixed clocks, non-Send values, bounded budgets and a fixed-seed 300-step interleaving. Private [counter checks](../../../tests/domain/query_cache_internals.rs) remain under the domain cfg(test) boundary. The [browser fixture](../../../tests/browser/p02-query-cache.cjs) runs the same owner in WASM without transport or storage writes. See [verification](query-cache-verification.md) for exact results. No P00/P01/P02 exit, feature-complete cache or production backend/playback claim is made.
