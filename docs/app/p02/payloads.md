# Bounded portable payloads

This P02.07 continuation adds actual byte-limited serialization of normalized song-summary pages and the existing retained queue snapshot, with exact encoded byte/item accounting for the portable query cache. It does not select a backend wire format, remote message protocol or durable cache. [ADR-015](../adr/015-bounded-payloads.md) records source evidence, target limits and alternatives.

## API and bounds

The [storage payload module](../../../crates/storage/src/payloads.rs) exports `encode_song_page` / `decode_song_page`, `encode_queue` / `decode_queue`, `Limits`, `SongPagePayload`, `QueuePayload` and fixed `Error` categories. Byte limits must be 1 through 1,048,576; item limits may be zero through 10,000. Defaults are the upper bounds. The separate [durable profile/import/journal/state encoder](serialization.md) retains its 256 KiB limit.

A `song_summary_page` envelope contains version 1, explicit server ID, start index, optional total count and ordered song ID/name/duration_ms rows. The server remains present for empty pages. Encoding and decoding verify the expected server; rows inherit that scope. IDs must be nonblank and at most 128 UTF-8 bytes; names are at most 1,024 bytes. IDs are validated without changing their text. Unknown count and known zero stay distinct; no uncharacterized relationship between total count and page start is imposed. Integer milliseconds and page indexes round-trip through u64 in the Rust codec, including values above JavaScript's exact-number range. A future JavaScript wire protocol needs its own numeric policy.

A `queue_snapshot` envelope reuses the existing retained QueueSnapshot, including occurrence order, priority, shuffle permutation, current occurrence and resume position. The shared retained-queue validator rejects duplicate occurrence IDs, dangling or repeated priority entries, invalid permutations and mismatched current/resume identities. Different occurrences of the same song remain distinct, with each occurrence retaining server scope. This is the existing [retained projection](imports.md), without full runtime metadata or a new queue owner.

Both opaque payload values retain only encoded bytes and item count. Their `weight()` returns the exact UTF-8 byte length and number of rows/occurrences for QueryCache. Debug exposes numeric counts only; errors contain no parser messages, IDs or text. Schemas have no authenticated URL or credential fields, but arbitrary text is not inspected for secrets. Raw bytes belong only in the intended consumer boundary, not diagnostics.

## Validation and ownership

The encoder validates item/string/identity rules before output and uses the bounded writer while serializing. Borrowed row adapters and queue references avoid a full JSON Value, intermediate row vector or queue clone. Overflow returns no partial payload. The decoder rejects oversized input before typed parsing, rejects unknown fields/malformed values/future versions and revalidates identity/queue rules before returning data. Item counts are checked after typed parsing; temporary DTO vectors/strings and page conversion overlap are bounded by input bytes rather than a hard heap allocation budget. Caller-owned data, allocator overhead and transport buffers remain outside this accounting.

Exact query/filter/library/page keys, current request/generation and deadline/cancellation remain the caller's responsibility. Encoding a page does not prove it answers a particular filter, and decoding does not authorize a cache publication. The [deterministic integration fixture](../../../tests/storage/payloads.rs) pairs a matching page with real QueryKey/Ticket values, derives Weight, publishes through QueryCache, checks server/page/library isolation and rejects cancelled/stale work without replacing the prior value. Existing cache diagnostics remain fixed counts only.
