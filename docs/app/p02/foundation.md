# P02 portable foundation

`feishin-domain` implements the P02.01-P02.03 foundation contracts from Feishin commit `7d6ad318c79802e226996cfc39acba6b05bb22e8`. It has no third-party dependencies, I/O, runtime or UI imports. This is a contract increment; P02 persistence/import/cache gates and P05 queue/playback behavior remain separate work.

The normalized models cover songs, albums, album artists/artists, playlists and entries, folders, genres, users, music folders, radio stations, non-secret server profiles, tags, library detail information and structured lyrics. Song metadata retains artists/participants, replay gain/peak, original/release dates, technical fields, tags, artwork and resumable positions. Required nullable values use `Option`; optional nullable values use `Field::{Absent, Null, Value}`. Optional non-null values use `Option`. Related IDs inherit their enclosing entity's server scope. Standalone entity models carry the server explicitly. Partial ISO dates and timestamps stay strings pending adapter parsing; no date precision is invented. Backend-normalized integers must be range-checked by adapters.

List queries preserve server, sort, order, pagination, search, music folders and entity-specific filters, including unknown versus empty selections. The full source sort/feature vocabulary has stable string mappings and a tracked fixture. Backend-specific `_custom` bags and sort translation maps stay in adapters; a sort enum does not promise backend support. Features retain exact supported version membership, including sparse lists. Permission and playback capabilities remain separate from server features. Backend discovery/version-to-feature maps are not implemented.

Server/song/album/artist/playlist/playlist-entry/queue-occurrence/device/folder/genre/user identities have distinct types. `Scoped<T>` prevents same-ID songs on different servers from comparing equal. Queue occurrence and playlist entry identities preserve repeated songs. Playback position and listened duration are distinct. Nonnegative finite `Seconds` convert to integer milliseconds or Jellyfin ticks with checked overflow and truncation toward zero; ticks truncate to milliseconds and millisecond-to-tick multiplication is checked. Upstream normalizers use milliseconds (`jellyfin-normalize.ts:175`, `navidrome-normalize.ts:281`, `subsonic-normalize.ts:212`). Fractional milliseconds are deliberately represented at integer-millisecond precision; adapter parity fixtures must characterize any observable sub-millisecond difference. Lyric offsets are signed milliseconds.

The bounded example `Owner` demonstrates private state, typed commands/effects/completions and checked revision/generation/request counters. It only accepts replacement loads and additions. Later requests supersede earlier ones. Completion must match the entire pending context and arrive no later than its deadline; local additions invalidate pending replacement. Duplicate occurrence IDs, oversized replacements, deadlines and failed loads do not mutate the item snapshot. Matching terminal results clear the pending request; stale results do not clear a newer request. The revision identifies accepted item changes, not request scheduling. This is not the P05 queue reducer, shuffle/priority representation, playback state machine or scrobbling policy.

Backend, opaque payload transport, monotonic clock, RNG, non-secret persistence, secret store and playback traits use local boxed futures without `Send`. Tests implement all boundaries with `Rc`-backed state. Backend reads return normalized models; wire DTOs, authenticated URL construction and envelope parsing belong to adapters. Playback commands include play/pause/resume/stop/seek; events identify the request/generation and occurrence. Engine capabilities explicitly describe pause, seek, gapless, crossfade, speed, filters and audio analysis. Typed capability checks reject unsupported features; command checks gate pause/resume/seek before dispatch. These flags do not implement advanced engine operations. Secrets have no `Debug` implementation; explicit exposure is available for adapters, without a secure-memory/zeroization claim. Storage keys and secret identifiers must be namespaced and validated by concrete services.

Every asynchronous port receives correlation, deadline, cancellation and request/response/item limits. `OperationContext` provides deterministic validation helpers; adapters must call them before I/O and after completion, bound buffers/tasks and stop work when cancelled. The type itself cannot enforce concrete I/O scheduling. Error categories distinguish cancellation, deadline, unsupported capability, invalid input, authentication, network, wire parse, server protocol, rejected operation, storage, playback, stale result, capacity and counter exhaustion. They intentionally contain no credential-bearing error strings; adapter diagnostics/localization need separate redaction policies.

The backend trait currently exposes song/detail/list/capability reads as a useful conformance surface. The rest of `ControllerEndpoint` operations (authentication, mutations, stream/transcode/image requests, search/radio, scans, ratings, sharing, reporting, jukebox and server queue operations) remain P03/P04 adapter work, not claims of complete API coverage. Lyrics values are modeled; parsing/provider behavior remains P09 work. Persisted DTOs and actual secret/playback implementations are outside this crate. No real network, audio/device, browser runtime or end-to-end parity is established.

Verification uses `tests/domain/foundation.rs` and tracked synthetic fixtures under `tests/fixtures/p02/domain/`. The catalog fixture is transcribed from pinned source declarations; the song fixture is synthetic normalized data, not a backend response. Catalog checks compare complete records with LF/CRLF line terminators removed, preserving exact names, value order and whitespace. A regression exercises both checkout formats and rejects renamed, missing, added, reordered and whitespace-altered values. Tests cover full enum vocabulary, exact sparse feature membership, nullable/omitted metadata, server and occurrence identity, unit and counter edges, stale/forged/deadline/failure/capacity owner paths, all local-future boundaries, deterministic clock/RNG/cancellation and unsupported playback dispatch without side effects. Four compile-fail doctests cover ID and time-category confusion. The test harness is explicitly wired in the crate manifest. Native tests execute; WASM checks compile the same test doubles without claiming browser execution.
