# ADR-003: native playback replacements and browser policy

Status: boundary decision recorded; specific engine/library and fallback feasibility pending P01. No native audio dependency is added in P00.

Start P01 evaluation with managed mpv JSON IPC as the desktop default candidate. Preserve process/socket/named-pipe ownership, command correlation/deadlines, observed properties, current/next preload and bounded graceful/forced shutdown. The reference requires an external mpv binary; its README identifies 0.35/0.36 as known working and 0.34 as broken, which is historical source evidence, not a new compatibility promise. The rewrite must test its selected version and state whether release packages bundle it.

| Upstream surface | Native strategy to demonstrate | Browser strategy |
| --- | --- | --- |
| mpv/local | Managed process actor, generation isolation, executable/argument validation, device and property errors | Not a local browser engine |
| Web two-player gapless/crossfade | Measure mpv capabilities; compare an existing native audio library or bounded second native engine for missing dual-stream transitions | Browser media elements with WebAudio gain/DSP behind WASM adapter |
| WaveSurfer waveform | Native waveform data generation/display with readiness/cancellation and bounded caches; investigate actual source reachability before disposition | Browser waveform/media adapter where supported |
| mpv startup fallback to web | Explicit native fallback candidate must play representative authenticated streams, seek, switch and tear down; no silent switch to a desktop webview | Codec/autoplay/CORS negotiation and explicit failure; jukebox only when supported |
| EQ/compressor/speed/pitch/gain/device | Compare native engine filters and device controls against upstream cases and measured audio | WebAudio and media capabilities; unsupported controls explicit |
| Analysis/visualization/capture | Native bounded samples or authorized OS capture and preset renderer; bridge boundary/cost in ADR-008 | Browser audio nodes and permitted capture only |
| DLNA and server jukebox | Separate adapters sending typed commands/events through the same state owner | Jukebox if advertised; remote can control desktop casting |

P01.05 must test source failure, missing/wrong binary, stalled quit, process death, late callbacks, rapid engine switch, gapless/crossfade timing, filters, waveform readiness and audio analysis on the required matrix. P01.08 covers capture denial/minimize/disposal and representative preset cost. Record actual audio/device evidence; unsupported required capabilities block the gate until a bounded remediation is accepted. A custom decoder and general JavaScript bridge are not initial defaults; either needs a separate measured decision. A bridge must have bounded IPC, lifecycle, dependencies/notices and CPU/RSS/GPU cost, without becoming a second playback state owner.

Browser default is browser media/WebAudio, conditional on actual stream, codec, CORS and autoplay tests. Do not assume mpv's codecs imply browser support or use browser playback as a native fallback without evidence. Engine capabilities, server capabilities and user permissions remain separate.

P01 continuation: [native candidate measurements](../p01/continuation.md) evaluate ffplay/SDL initial seek and teardown after missing-mpv failure, plus offline FFmpeg concat/crossfade/lowpass/waveform output. ffplay has no control IPC and is not adopted as the production fallback; dynamic seeking/pause/device/stream handoff and real transition timing remain open. Browser session callbacks, generation cancellation/deadlines and explicit reload recovery now have lab evidence, including unresolved Firefox/WebKit seeking cases. No hidden webview, custom decoder or second production queue owner is introduced.

P01 Windows IPC candidate: [the transport record](../p01/windows-ipc.md) isolates named pipes behind the existing blocking worker interface. Target-only Tokio 1.48.0 and interprocess 2.4.6 supply cancellation-safe async reads/writes and safe server-PID queries while preserving the workspace's unsafe-code prohibition. A current-thread runtime, immediate local opens with identification-only security quality of service, absolute command deadlines and direct Tokio handle disposal avoid a second playback owner or detached connector/flush workers. Only a duplicated metadata handle uses the synchronous interprocess wrapper for PID inspection. Its Tokio OwnedHandle conversion is excluded after review found incorrect error-path ownership. Direct Win32 overlapped FFI would add resource/cancellation safety obligations; synchronous pipe APIs need separate deadline/flush handling. This is a bounded prototype decision, with Windows runtime/real-mpv, integration and resource evidence still required before production adoption.

P01 browser seeking follow-up: the [controlled comparison](../p01/browser-seeking.md) corrects a forced-loop test setting. Default non-looping interior seeks completed on all three lab engines; Firefox exact-end decode and WebKit end-return/looping behavior remain open. Completion events/errors/timeouts are recorded separately from position and shell completion. No application engine, server policy or supported-target decision changes; browser acceptance still requires the declared matrix and bounded failure handling.

P01 seek lifecycle remediation: the [bounded browser callback request](../p01/seek-deadlines.md) owns one eight-second deadline with cancellation/generation rejection. Rejection, mismatch or timeout pauses and requires visible reload; Media Session Play and native play/playing events enforce the latch. Native control seeking remains browser-managed and open for separate verification. A settled same-position request needs no event. This addresses adapter liveness/error reporting without claiming browser codec/looping repair or an upstream defect. The portable domain, native engine and production queue owner are unchanged.

P01 native transition continuation: [owned monitor measurements](../p01/native-transitions.md) compare prefetch off/on using actual managed current/next playback and a real pause control. Captured energy windows do not certify sample conservation, device gaplessness or live crossfade. The managed launch now includes the upstream scripts-disabled default; private runtime property checks verify it. Native fallback and production prefetch settings remain undecided, with the required matrix still open.

P01 dual-mpv continuation: the [crossfade experiment](../p01/crossfade.md) evaluates one owner controlling two managed processes, source-derived slider/scalar curves and an observed cubic percentage law. It does not select a production dual-process mixer or native fallback. Source replay exposes the exponential outgoing inversion and squared volume mapping; no audible-parity or constant-power claim is made. Scheduling/cost, lifecycle policies and the target matrix still gate adoption.

P01 browser element-seek continuation: the [observed seeking event](../p01/native-control-seeking.md) shares the callback deadline and latest-target policy. Browser element events do not identify the physical control or carry request generations; actual scrubber/device input and finite-duration/browser matrix limits remain separate. This is not native desktop media-control routing.

P01 native position continuation: [bounded position queries](../p01/native-position.md) preserve normal unavailable values and cap each IPC operation by the remaining caller budget. Normal unavailability matches the upstream read boundary; unexpected errors remain typed failures instead of following its broad catch-to-undefined. Paused test-only waits distinguish command acceptance from observed arrival. The raw seek API does not promise a playback/device completion event; production state ownership and the engine/fallback matrix remain open.

P01 native-control continuation: [a bounded worker and opt-in Linux MPRIS adapter](../p01/native-controls.md) route typed requests through one managed engine, with generation/request identities, cancellation, queue pressure and shared deadlines. A caller-owned private bus exercises the partial single-source adapter; it does not register on the host session by default. Engine queries distinguish pause, loading and natural EOF. Observed seek signals, protocol no-op inputs and typed malformed replies are covered independently of physical keys/device output. Production queue/handoff/fallback, authenticated sources, unsolicited EOF notifications and full OS/MPRIS behavior remain open. The optional Linux-only zbus/async-io dependency boundary reuses pinned lockfile versions and does not enter portable core or WASM.

P01 replacement continuation: [serialized same-mpv replacement](../p01/native-handoff.md) uses one supervisor, a one-slot queue and monotonically admitted generations. It retires old control endpoints and waits for cleanup before creating a replacement; any cleanup error stops further replacement. Endpoint installation is separate from engine/source readiness. This deliberate ownership policy strengthens the source's unawaited restart sequence without claiming timing parity. Static inspection also found that upstream's startup-fallback notification is logged by its renderer subscriber, with no observed type-changing consumer; automatic fallback is not established by that label. The source finding is not a runtime defect certification or a product decision to remove fallback. A controllable alternative, authenticated-stream/source restoration, capture/OS integration and supported-platform/device evidence still gate native fallback adoption. No fallback dependency or production engine is selected.

P01 candidate continuation: [an opt-in isolated GStreamer playbin helper](../p01/gstreamer-candidate.md) demonstrates a controllable alternative over the existing bounded process/IPC experiment. Safe gstreamer-rs 0.24.4 bindings and native calls stay in a null-output child; default desktop, core and WASM do not link it. Owned local/query-authenticated loopback WAV/FLAC/MP3 controls and observed seeks have lab evidence. Process containment is preferred here over an in-process prototype because Rust thread teardown cannot force cancellation of a stalled native call. This adopts only the experimental boundary, not GStreamer as the production fallback. Automatic selection, cross-engine source/position restoration, device/DSP/capture/OS and platform/performance/native-license gates remain open. Single timing samples with different load/preroll boundaries do not select an engine.

P01 prepared replacement: [explicit local source preparation](../p01/prepared-handoff.md) now shares the same supervisor and control owner across mpv/GStreamer. The caller supplies source/position/pause/volume intent; the owner retires the previous endpoint, pauses before load, observes readiness/seek/readback/status and only then publishes the replacement. One capped admission deadline includes queueing and preparation; cleanup keeps its separate safety budget. Failure never revives a retired endpoint, and cleanup uncertainty still stops admission. This is an experimental readiness/ownership decision with regression fixtures, replacing fixed-delay assumptions for this probe only. Automatic fallback selection, old-state capture, source/occurrence/authentication and consumer handoff remain production decisions; physical gain/output continuity and full platform support are unverified.
