# ADR-013: bounded Subsonic protocol foundation

Status: accepted for a bounded P03.02 continuation under the maintainer's 2026-10-29 instruction to continue implementation with a managed second orchestrator. P02 remains open. This records sequencing authorization for this task, not a P02/P03 exit or a waiver of source, live-server, browser, engine or packaging evidence. [ADR-012](012-subsonic-request-foundation.md) continues to govern authentication, encoding and credential boundaries.

## Pinned source evidence

Feishin `7d6ad318c79802e226996cfc39acba6b05bb22e8`, `subsonic-api.ts:394-425`, checks `subsonic-response.status`, coerces an error code with JavaScript `Number`, treats code 40 as authentication failure and substitutes other nonzero codes into the reported HTTP status. Code 0 suppresses notifications/status replacement. The separate `silentlyTransformResponse` at lines 468-477 replaces a non-ok response's error code with 0. These are static source observations; this continuation does not claim new runtime replay of those expressions.

`subsonic-api.ts:526-564` sends all default/auth/query parameters as repeated RFC3986 pairs in a form body when the server feature is present. Its earlier special branch handles JSON POST for `getTranscodeDecision.view`. `subsonic-controller.ts:1432-1510` first pings, requires both `openSubsonic` and `serverVersion` before extension discovery, copies extension name/version entries with last duplicate winning and subsequently probes jukebox. Missing extension arrays yield empty features. Source schema `subsonic-types.ts:409-422` defines optional discovery fields, with string names and numeric version arrays. Stable inventory anchors and target dispositions are in the [migration map](../migration/p03-protocol.csv).

## Decision

Keep HTTP/protocol wire values and parsing inside `feishin-subsonic`. Reuse portable domain operation contexts, monotonic millisecond clocks and local futures without adding a Send bound or a runtime. Separate HTTP failures, protocol failures, malformed wire data, network failures, cancellation, deadline, stale correlation, capacity and unsupported operations. Errors never retain backend messages, bodies, authenticated URLs or nested transport errors. Opaque request/response values have redacted Debug output. There is no automatic retry or authentication-state mutation.

A failed envelope remains an error even for code 0 or a silent request. This deliberately replaces the source notification/status conflation: code 0 cannot establish successful mutation or successful discovery. Integer numeric and integer-string codes are accepted; authentication code 40 is distinguished. Unknown protocol codes remain protocol failures. Malformed JSON/envelope/typed discovery fields fail closed. Arbitrary server message text is discarded rather than handed to diagnostics.

Discovery uses only the advertised response from the selected authenticated server. No backend family implies support. Ping without both OpenSubsonic and a nonempty server version ends with no extensions. Missing extension arrays mean none; malformed entries are rejected. Duplicate names use the last advertised version list. Version support uses explicit membership, and empty lists grant no feature. Form POST requires advertised `formPost` version 1. This is deliberately stricter than source presence-only feature mapping, whose empty or future-version arrays can otherwise enable the branch. Unknown extensions are ignored after shape/version validation and never enable known operations.

Bind discovery to its canonical server base so one server cannot authorize another server's form request. Form planning keeps the existing encoded-once parameters and reserved-override rejection. An explicitly permitted form request moves those parameters from the query to an opaque form body and sets `application/x-www-form-urlencoded`. Required form mode returns unsupported without the supported version; optional preference may use GET. The transcode-decision JSON branch, general endpoint operations and jukebox probe remain deferred. This foundation does not imply their support.

Use the domain's inclusive deadline boundary: `now == deadline` is permitted and `now > deadline` fails; cancellation has priority. Validate context and request limits before transport, validate cancellation/deadline/correlation after completion, require HTTP 200 for discovery as the source does, reject oversize responses before JSON parsing, and bound extension collections. Recheck completion context after parsing. Native/browser transports must also bound allocation and cooperate with cancellation/deadlines while I/O is pending. There is no platform timer, network driver or forced termination of uncooperative pending I/O in this foundation. A response rejected after a mutation cannot prove the remote side did not apply it.

## Alternatives and consequences

A production HTTP dependency now would select native/browser redirect, TLS, streaming and executor policies ahead of their integration evidence. Returning Axios-style errors or arbitrary backend messages would violate credential redaction. Mapping protocol error codes into HTTP status would lose error identity. Retaining discovery versions permits later explicit capability composition without assuming every server family exposes the same extensions.

Deterministic non-Send doubles establish local parsing, request planning and guard behavior. They do not prove CORS, TLS, redirect safety, secure entropy, actual socket cancellation, streaming allocation bounds, live login or real server conformance. See the [protocol contract](../p03/protocol.md) and [verification record](../p03/protocol-verification.md). All broader P03 tasks and P00/P01/P02/P03 exit gates remain open.
