## Local ordering and RNG

Implement every source local sort branch. Name is lowercase UTF-16 order with stable ties; sortName uses its case-sensitive source name fallback. ID means source order or literal reversal. Song count preserves raw missing-versus-null sort keys even though both normalize to None. Duration sorts by the validated source floating millisecond value, preserving sub-millisecond order while published duration remains checked integer milliseconds. Rating, created text and release year retain source scalar/null ordering. Album-artist sorting reads a missing primary source field and therefore uses name ascending in either direction. Favorite sorting also reads a missing field; play/last-play counts normalize to null. Those and unhandled variants retain source order rather than gaining inferred capabilities.

Local random sort uses the source forward shuffle and consumes one RNG draw per row, including the final one. Each u64 supplies its upper 53 bits as a Math.random-compatible fraction, with checked row-relative indexing. Sort direction has no effect on shuffle. General/search server-random paths consume no local RNG. Authentication entropy remains a separate boundary. Tests use shared Rc/Cell RNG state to establish non-Send compatibility and exact draw counts. No uniformity or secure-entropy guarantee is inferred for a caller's Random implementation.

## Date decisions and characterized differences

The checked normalizer emits full lexical ISO dates or integer-year strings. For local release-date ordering, interpret those at UTC, including source ISO day rollover, legacy integer-year parsing and JavaScript's date clip range. Preserve source quirks such as year 1 parsing as January 2001 and small negative legacy strings parsing like their absolute values; six-digit signed expanded years remain signed. Unknown dates use epoch 0 as the source helper does. This is a narrow parser for normalized Subsonic output, not a general external date parser.

Legacy Date.parse depends on the host timezone. A pinned original-controller probe on albums with years -1000 and 1000 orders positive before negative at UTC but negative before positive in Europe/Bratislava. The target deliberately uses UTC consistently for native/WASM instead of depending on a platform timezone provider. The fixture retains both original observations; runtime local-time parity for these legacy edge strings is not claimed.

Lodash's invalid-date comparator is not antisymmetric: invalid ties retain order ascending but can reverse descending. Rust ordering uses a total relation with stable invalid-date ties, without falling through to a name key. A regression records the original descending order and an explicit target order for that one case. This correction is not hidden by rewriting source expectations. Other date cases, including impossible ISO days and clipped years, compare against original UTC results. Existing checked metadata/ID/time and missing-title sort-name decisions from ADR-014/ADR-016 remain.
