# ADR-008: P01 visualization and capture feasibility

Status: bounded prototype recorded; production source, preset compatibility and all-platform capture decisions remain open. No specialized-library bridge or Japanese conversion choice is accepted by this spike.

An original spectrum/waveform preset is drawn by egui from a portable bounded analysis frame. It is representative of the upstream audioMotion surface, not a Butterchurn preset interpreter or a port of its presets. The native experiment resamples mono PCM to 8 kHz through an external FFmpeg process, takes 256 samples per frame and computes 16 selected DFT bins through Nyquist. Retain one newest frame only. Reject invalid lengths/non-finite input and clamp amplitudes. Browser WebAudio supplies its own sample rate; bin frequencies therefore differ and are not a shared frequency-calibrated spectrum contract yet.

Capture is an explicit `--capture-monitor SOURCE` opt-in on Linux PulseAudio/PipeWire. The source name is validated and passed as one process argument, with no shell. No microphone/monitor is selected automatically. An isolated `p01_owned` null sink carried an owned 750 Hz mpv tone into FFmpeg analysis; no host desktop/microphone capture was performed. Generated input, unavailable source, child shutdown and capture-first/engine-second teardown are separate tests. Missing source failure does not prove OS permission denial prompts. Closing/minimizing or disabling the native consumer disposes capture on a bounded supervisor worker. The P01 continuation re-enables the same explicitly configured session source and latches failures until off/on retry; queued old-generation frames are rejected. Browser visibility/pause/consumer state controls the analysis interval without stopping audio playback.

The upstream anchors are `src/main/features/core/visualizer/index.ts:9:49` / `:13:48` and `src/renderer/features/visualizer/components/audiomotionanalyzer/visualizer.tsx` at baseline `7d6ad318c79802e226996cfc39acba6b05bb22e8`. The original visibility guard allows display capture only for the local playback type and a visible local visualizer. This spike keeps explicit source consent and disposal rather than reusing Electron display-media APIs.

Remaining P01 remediation, all still required before exit:

- Measure presented frame/CPU/GPU/RSS costs with actual playback and capture on the declared reference hardware, including hidden/disposed/re-enabled cases and rapid engine switch. CPU-only concurrent and synthetic/owned-process lifecycle evidence now exists in the [continuation](../p01/continuation.md); physical measurements and complete engine handoff remain open.
- Demonstrate supported Windows/macOS authorized capture APIs, actual permission denial and resource disposal. Linux monitor access alone cannot certify those platforms.
- Compare a representative actual upstream preset strategy. If a specialized renderer/library bridge is necessary, pin its license/version and bound samples, IPC, process ownership, timeouts and cost before acceptance; keep one playback owner. No hidden webview is introduced.
- Test browser visible/hidden analysis, CORS-tainted/denied input and mobile permission behavior with actual device output. The fixture browser clock is not audible-output evidence.

Alternatives remain mpv-native analysis output, platform loopback/portal capture and a measured specialized preset library. A custom decoder and general JavaScript runtime would expand the scope and are not adopted. Full rendering/capture and Japanese lyric conversion remain P12/P09 work after these feasibility gates; no production feature is marked ported. See [P01 verification](../p01/verification.md).
