# ADR-014: bounded Subsonic song detail normalization

Status: accepted for the bounded P03.03 `getSong` continuation assigned by the orchestrator under the existing maintainer sequencing instruction. P02 and broader P03 gates remain open. [ADR-012](012-subsonic-request-foundation.md) and [ADR-013](013-subsonic-protocol.md) continue to govern request/authentication and exchange boundaries.

## Source evidence and decision

Pinned Feishin `7d6ad318c79802e226996cfc39acba6b05bb22e8` `subsonic-controller.ts:1528-1541` calls `getSong` with the requested ID, requires HTTP 200 and invokes `ssNormalize.song` without a playlist index or disc map. `subsonic-normalize.ts:21-269` defines the artist/participant/genre/date helpers and song normalization. `partial-iso-date.ts:3-30` returns finite numeric years unchanged and validates dates by lexical digits only. `subsonic-api.ts:571-584` invokes optional diagnostic validation and returns the original envelope; unknown `releaseDate` is therefore not presumed stripped merely because the diagnostic song schema at `subsonic-types.ts:179-217` omits it.

Implement one free async song-read operation over the existing local transport and operation context. Keep wire parsing and normalization inside `feishin-subsonic`; do not introduce a broad facade implementation with shallow or unsupported placeholders. Use explicit scoped identity, retain source normalizer field/default semantics and reject a mismatched returned ID as stale. Base/auth/profile association stays the caller's responsibility because the existing domain context has no server binding. No domain schema expansion is necessary for this operation.

The [hash-bound replay](../../../tools/app/p03-song-reference.cjs) extracts nine original arrow expressions from hash-checked source and transpiles them with a hash-checked TypeScript compiler. No upstream module initialization, installer, lifecycle hook or network request runs. Source enum bindings are taken from hash-checked `domain-types.ts`, including uppercase `CLEAN`/`EXPLICIT` values. Source expressions remain in ignored local evidence; tracked fixtures contain synthetic inputs and normalized outputs with provenance hashes. The replay characterizes observable source behavior, including empty-array suppression, remixer duplicates, raw created strings, impossible calendar dates and zero/default handling. It is not live server conformance.

## Deliberate representation and validation differences

Validate the caller's server identity before dispatch using the persisted P02 profile boundary (`crates/storage/src/lib.rs`, `Profile::valid`): nonblank after whitespace trimming and at most 128 UTF-8 bytes. Retain the original identity bytes rather than trimming them. This target profile constraint is distinct from source song IDs, which retain the existing request query limit and may exceed 128 bytes. Regression tests reject blank/oversized server identities without dispatch and accept an exact 128-byte Unicode server identity with a 129-byte source song ID.

Store the song normalization/returned-ID result before the final operation-context check, mirroring the protocol envelope completion policy. Cancellation or deadline observed after normalization takes priority over either a normalized song, malformed data or stale returned identity. A scripted clock keeps entry, transport and envelope checks valid and advances only at the song completion check; regression cases exercise malformed fields, a missing song object, wrong returned ID and successful normalization, with deadline and cancellation outcomes.

The diagnostic upstream schema is not enforced as a complete input contract. Accept missing old-server artist arrays/path/disc fields when the normalizer has a defined fallback. Require ID, title, created, content type and size because domain output needs these values and content type is directly accessed by source. Validate types of consumed optional fields; absent/null optional values share source falsy fallbacks. Validate consumed nested entries rather than relying on unchecked JavaScript property access. Ignore unrelated wire fields rather than requiring diagnostic-only `isDir`, `isVideo`, `parent`, `suffix` or `type`. Favorite accepts booleans or timestamp strings; arbitrary numeric/object truthy inputs are rejected. Malformed input always yields a constant category, without retaining the payload.

Numeric IDs must be integral safe JavaScript integers (absolute value at most 9007199254740991) or strings. Fractional/unsafe numeric IDs accepted by generic source `.toString()` are deliberately rejected; negative zero becomes `"0"`, matching JavaScript. Unsigned integer domain fields reject negative, fractional or unsafe numeric values instead of truncating, overflowing or silently inheriting JavaScript precision loss. Floating BPM, rating and gain values remain finite numbers. Year must fit integer `i32`: fractional/out-of-range track years, which source `coerceYear` permits, are deliberately rejected. Complete release-date numeric parts still follow the source lexical result, including year zero on invalid shape; there is no calendar repair or partial-date invention.

Domain duration uses the existing checked nonnegative seconds-to-milliseconds conversion. Fractional milliseconds truncate toward zero; negative or overflowing durations fail as malformed instead of producing JavaScript negative/floating/unbounded milliseconds. The replay includes a 1.2345-second example, asserting the documented domain projection of 1234 milliseconds. This is a unit representation choice, not a claim of bit-exact floating duration parity.

Domain `Option` collapses source null and omitted values: omitted gain/peak components become `None`, and an omitted detail playlist-item ID is `None`. Absent source `isResumable`/`resumePositionMs` map to existing domain `None`. The comparison normalizes these representational distinctions only; every source-emitted song field is otherwise compared. Constant source null fields remain absent; unrelated wire `timestamp`, `_custom`, comments and artwork URLs are not copied into domain.

The source participant grouping uses `role in {}` and calls `.push` on inherited properties for roles such as `__proto__`, `constructor` and `toString`, throwing TypeError. Three replay fixtures characterize this source failure. The adapter rejects all inherited Object.prototype role names as malformed after subrole composition, preserving failure instead of silently returning successful metadata or leaking JavaScript exception details. A subrole that yields an ordinary distinct key remains allowed. Numeric negative-zero IDs stringify to `"0"`; negative-zero release month/day pad to `"00"`, preserving source zero formatting.

## Consequences and alternatives

A general deserialized backend schema would over-require fields that old-server fallback behavior does not use and could strip extensions before normalization. Unchecked dynamic JSON would retain source crashes/coercion ambiguity. Small private typed accessors retain the defined behaviors while enforcing domain bounds. No new dependency or portable-domain change is needed. Collection/output limits bound work locally; they do not establish total allocation bounds or transport reception limits. Production transport, common backend adoption, generic/extension-enabled server conformance and the remaining P03.03/P03.04 work need separate implementation and evidence.
