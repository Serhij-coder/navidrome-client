# ADR-016: bounded album and album-artist detail reads

Status: accepted for bounded P03.03 continuation, 2026-10-29. Existing phase exits and production transport remain open.

## Evidence and model

Pinned Feishin `7d6ad318c79802e226996cfc39acba6b05bb22e8` controller `getAlbumDetail` at `577:21` calls getAlbum with ID and normalizes the HTTP-200 album. `getAlbumArtistDetail` at `483:27` calls getArtist, normalizes its artist and optional embedded albums, then forces similarArtists to null. Shared normalizers at `subsonic-normalize.ts:271:30`, `:323:24` and `:334:24` govern artists, primary release type and albums. The full source types declare AlbumArtistDetailResponse as AlbumArtist or null (`domain-types.ts:892`), although this controller also emits the optional albums property. The target adds one portable AlbumArtistDetail wrapper with normalized artist and optional albums; absent and empty albums differ. Wire parsing stays in the adapter. The selected adapter returns Result for its non-null detail operations; no facade-wide nullable fallback is implemented.

Use the existing guarded local transport and normalized models, with small shared private song helpers. Album songs reuse the existing song normalizer and gain discSubtitle from the raw disc number, defaulting missing/null to 1. Source discNumber uses a separate falsy default, so a raw zero can yield normalized discNumber 1 yet look up disc-title key 0. Duplicate disc-title keys keep the last title, and repeated song IDs remain in order. Missing/null song arrays become empty songs, matching actual normalization rather than the stricter diagnostic schema. Artist missing/null album arrays remain absent; explicit empty arrays remain present and empty. Incoming similar-artist entries are validated but not retained; source evaluates their map before overriding the result.

## Deliberate differences and budgets

The source sets album sortName from item.title. A missing title emits no sortName and null emits null despite the declared string type. Exact original-expression/controller fixtures characterize both cases. Use the album name when title is missing/null, preserve an explicit empty title, and reject other invalid types. This is a deliberate correction to maintain the existing portable string invariant, not a claim of exact source output for that field.

Require the consumed album ID, name, artist, created and duration fields. Source missing artist can emit an omitted required string, and null/missing duration can produce zero/NaN; fixtures characterize these malformed source successes and the target rejects them. Existing ADR-014 checked integer milliseconds, safe numeric IDs/counters, i32 years, malformed consumed values and fixed errors continue to apply. Disc-title keys must fit unsigned u32, matching the portable Disc model; fractional/out-of-range keys fail rather than being coerced or truncated. Decimal artist albumCount strings (including whitespace, empty and exponent notation) normalize to nonnegative safe integers; malformed, fractional, unsafe or non-decimal forms fail. The source Number conversion can yield NaN or accept additional coercions; a fixture records NaN serializing to null while the target explicitly rejects it. Artist starred timestamps remain strings (false/missing/null are absent); boolean true cannot represent a timestamp and is rejected. No authenticated URL is constructed or copied into normalized artwork fields.

OperationLimits.items is an aggregate normalization-work budget for these nested reads: count each root/nested artist, album and song plus every supplied artist/contributor/genre/disc-title/label/release-type/similar-artist row. Duplicate input rows still cost work. Scalar fallback metadata has bounded multiplicity per entity; this is not an exact object or heap count. Existing per-collection checks also apply. This prevents many individually small embedded albums from multiplying work past the requested budget. Existing getSong retains its documented per-collection semantics. Input byte checks occur at the existing transport completion boundary; actual streaming bounds, timers and wakeups remain the transport's responsibility.

Validate profile server identity before dispatch (nonblank, <=128 UTF-8 bytes), keep original identity text, and reuse existing query encoding limits for backend IDs. Reject mismatched returned root IDs as stale, an explicit target guard absent from the source controllers. Final context checks take priority over normalization/mismatch success or errors. Base/auth/server association remains caller-owned; no new authentication owner or runtime is introduced.
