# P01.04 bounded browser seek lifecycle

The browser feasibility adapter now owns one cancellable deadline and generation for Media Session callback seeks, independently of its play operation. Native audio-control seeking remains browser-managed; its deadlines and concurrent interaction with callback seeks remain open verification work. A new seek replaces the previous request. Source reload/replacement, media error, completion and shutdown cancel pending seek work. An unchanged, settled position completes immediately without waiting for a browser event. Non-finite positions remain ignored and finite requests stay clamped to duration.

The adapter catches a rejected `currentTime` setter and reports a generic failure. Missing completion reaches the eight-second browser timer deadline; mismatched completion, setter rejection and timeout pause playback, invalidate pending play/seek work and require the visible Load/Play action to reload. Media Session Play and the audio element's native play/playing events enforce that requirement while the failure latch is set, pausing any bypass attempt and stopping analysis. The visible action already clears the latch and loads the source before retrying. No browser exception, URL or credential enters the status message.

This is a bounded remediation for the missing/failing completion paths observed in the [seek comparison](browser-seeking.md), not a claim that browser codec/looping failures have been repaired. It is a feasibility adapter improvement rather than a characterized upstream defect: the source anchor `src/renderer/features/player/hooks/use-media-session.ts:26:32` delegates actions to the original player. No original-engine defect or full production parity is inferred.

The optional [lifecycle regression](../../../tests/browser/seek-lifecycle.cjs) runs through the real WASM adapter and Media Session callback bindings inside the [browser journey](../../../tests/browser/p01-browser.cjs). Its controlled faults replace only the fixture audio element's `currentTime` setter: first it throws a private disposable exception, then it accepts a request without starting a seek or emitting completion. The override is always restored. Tests check caught rejection, unchanged-position completion, the actual eight-second timeout, callback and direct-element failed-resume reporting, visible recovery, replacement by a valid seek, replacement by a different synthetic source and shutdown with pending seek work. Cancellation checks wait beyond the old deadlines on the real browser clock and require the later status/position to remain intact. No completion event is fabricated.

The observer separately records `already-at-target` only when the position was already equal to the target and settled before dispatch. This distinguishes an event-free no-op from a request that reaches the target later without a completion. The ordinary event/error observation still uses its original three-second deadline and position tolerance. The application timer is a browser event-loop deadline, not a physical input/device latency guarantee or a hard wall-clock guarantee for suspended pages.

The [manifest](evidence/seek-deadlines.json) binds final source overrides, release bundles and [before](../../../tests/fixtures/p01/browser/2026-10-23-seek-deadline/before.json)/[fixed](../../../tests/fixtures/p01/browser/2026-10-23-seek-deadline/fixed.json) results.
