# P01.05 native control ownership and private-bus adapter

`ControlSession` now creates and exclusively owns one managed mpv on a worker. Cloneable clients submit typed commands through eight ingress slots; each request has one reply slot, a generation, request ID, deadline and cancellation flag. Local path payloads are bounded to 4096 Unicode bytes. Queue pressure, stale generations, cancellation, expired requests, stopped sessions and engine errors remain distinct. Dropping a request cancels queued work; an IPC mutation already issued can have executed despite timeout or cancellation.

Construction and Drop of the control session do not wait on IPC. Shutdown sets a separate flag and cannot be starved by command traffic. The worker drains pending requests, reaps its process and reports cleanup through an explicit blocking wait intended for CLI/tests. Fatal transport or malformed successful DTOs end the worker automatically. Normal unavailable position/loading values preserve it. No UI or async executor runs blocking mpv or filesystem operations.

The existing mpv load/pause/seek methods retain their APIs; new deadline-aware helpers use the caller's remaining budget. Routed operations are capped at three seconds. Startup can consume the existing two three-second exchanges, followed by up to 600 ms protocol cleanup. These are protocol budgets: filesystem canonicalization, kernel scheduling and kill/reap latency are not bounded by them. No worker is spawned for an individual command and no production queue or fallback is introduced.

The optional Linux-only `mpris-probe` feature adds a real D-Bus service for one prepared local source. Its caller supplies an explicitly owned Unix bus address and a unique `org.mpris.MediaPlayer2.FeishinP01.*` name; there is no host-session lookup or default registration. Construction/teardown of this developer probe is blocking and belongs outside UI/async executors. Bus authentication/build/close and kernel latency are outside the routed-call budget. The caller must keep the source fixed while the adapter exists.

MPRIS Play/Pause/PlayPause, absolute/relative seek, position, volume and status use the same worker. Eight admitted calls share a two-second deadline across engine work and signal delivery. Async handlers poll bounded reply slots with timers rather than blocking the D-Bus executor. Playback status queries actual `idle-active`, position readiness and pause; idle/EOF is Stopped and loading is explicitly unavailable. No second playback state is stored. Natural EOF is query-visible; unsolicited EOF property notifications remain production follow-up work.

Absolute seek ignores stale track IDs, negative positions and positions past duration as required by MPRIS. A seek signal follows observed arrival within 0.1 seconds of the target under the original deadline; mere command acknowledgement is insufficient. This is an observed-position tolerance, not sample-exact or device timing. Relative seek past the single source's end returns unsupported rather than inventing a next track. Stop, Next, Previous, URI loading, application Raise/Quit, track lists, production metadata and global media keys remain unsupported. Volume is capped at 100 percent for this probe. Rate 1 is accepted; rate 0 pauses; other rates are unsupported. This is a partial single-source adapter, not full MPRIS or platform parity.

The [default controller tests](../../../tests/native-spike/control_session.rs) cover bounded ingress, stale/expired/abandoned work, shutdown during startup, short load/pause/seek IPC budgets, process death, malformed success DTOs and idle/loading status. The [private-bus tests](../../../tests/native-spike/mpris.rs) start and reap their own daemon, route real D-Bus calls to the controlled IPC peer, exercise checked microsecond conversions and no-op seeks, delayed arrival/no false seek signal, call pressure, teardown and status. The fixture's stateful modes are separate from the older position-race modes.

Run the owned null-output probes only with external mpv and dbus-daemon installed:

```sh
cargo test -p feishin-native-spike --test control_session --locked
cargo test -p feishin-native-spike --features mpris-probe --test mpris --locked
cargo test -p feishin-native-spike --test control_session real_mpv_control_routing --locked -- --ignored --exact
cargo test -p feishin-native-spike --features mpris-probe --test mpris real_private_bus_mpv --locked -- --ignored --exact
cargo clippy -p feishin-native-spike --features mpris-probe --all-targets --locked -- -D warnings
```

The opt-in real private-bus probe also plays a generated source through natural EOF and polls for Stopped. Neither probe opens a host bus, physical audio output, live profile or authenticated stream. CI invokes the feature checks on Linux and both real probes in the two Linux AppImage CPU jobs; hosted results must still be observed separately.

Traceability is pinned to `7d6ad318c79802e226996cfc39acba6b05bb22e8`: `src/main/features/core/player/index.ts:472:30` and `:588:35`; Linux MPRIS callbacks at `src/main/features/linux/mpris.ts:33:25`, `:39:24`, `:99:28` and `:105:24`. Upstream uses Electron dispatch and optimistic status updates; this experiment waits for worker acknowledgements and exposes actual engine queries. That is a prototype boundary, not a claim that every upstream command or OS workflow is ported. [MPRIS specification](https://specifications.freedesktop.org/mpris-spec/latest/Player_Interface.html) contracts are independent of upstream callback implementation.

Combined integration, artifact and review evidence is recorded in [the increment manifest](evidence/controls-input-manifest.json). Production handoff/fallback, authenticated sources, full native control/catalog behavior, Windows/macOS OS adapters, physical keys/audio and calibrated resource budgets remain P01 gates.

The first real controller probe issued a seek after load/pause acknowledgements and received `Rejected`. The initial real-bus probe likewise queried status before position readiness and received `PropertyUnavailable`. Both probes now pause before loading, observe readiness under one deadline and verify seek arrival without retrying mutations. Their assertion paths explicitly wait for worker cleanup before resuming a panic. These fixes change experiment sequencing, not the raw acknowledgement APIs. One later two-second seek deadline remained unexplained; subsequent repeated probes passed. This is retained as a runtime-budget limitation rather than a claim that its cause was resolved.
